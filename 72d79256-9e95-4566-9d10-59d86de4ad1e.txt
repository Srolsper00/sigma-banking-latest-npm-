## Overview

The AWS VPC Schema Mapping system provides a bidirectional mapping layer between the local VNet infrastructure (mathieu_et_favvarrow) and AWS Virtual Private Cloud (VPC) environments. This enables seamless hybrid cloud network operations while maintaining compliance and security standards.

## Schema Mapping Data Structure

### VPC Mapping Record

```typescript
interface VPCMapping {
  id: string; // Unique mapping identifier
  networkId: string; // Local network ID
  awsVpcId: string; // AWS VPC ID
  region: string; // AWS region (e.g., "us-west-2")
  availabilityZones: string[]; // AZ list for the region
  vnetMapping: {
    local: string; // Local VNet ID (mathieu_et_favvarrow)
    aws: string; // AWS VPC ID
  };
  cidrMapping: {
    local: string; // Local CIDR block
    aws: string; // AWS VPC CIDR block
  };
  createdAt: string; // ISO 8601 timestamp
  status: "active" | "pending" | "error";
}
```

### Example Mapping

```json
{
  "id": "vpc-map-1713178200000",
  "networkId": "net-1713178190000-xyz",
  "awsVpcId": "vpc-0abcd1234efgh5678",
  "region": "us-west-2",
  "availabilityZones": [
    "us-west-2a",
    "us-west-2b",
    "us-west-2c"
  ],
  "vnetMapping": {
    "local": "mathieu_et_favvarrow",
    "aws": "vpc-0abcd1234efgh5678"
  },
  "cidrMapping": {
    "local": "10.50.0.0/16",
    "aws": "10.50.0.0/16"
  },

}
```

## Implementation Details

### Creating a VPC Mapping

**API Endpoint:**

```
POST /make-server-4965418f/network/aws-vpc-map
```

**Request:**

```json
{
  "networkId": "net-1713178190000-xyz",
  "awsVpcId": "vpc-0abcd1234efgh5678",
  "region": "us-west-2",
  "availabilityZones": ["us-west-2a", "us-west-2b", "us-west-2c"]
}
```

**Process Flow:**

1. Validate that the local network exists
2. Extract network CIDR and VNet ID
3. Create bidirectional mapping record
4. Store mapping in KV store with key: `vpc-mapping:<networkId>`
5. Return complete mapping configuration

**CLI Command:**

```bash
$ vpc-map net-1713178190000-xyz vpc-0abcd1234efgh5678
```

### Retrieving VPC Mappings

**API Endpoint:**

```
GET /make-server-4965418f/network/aws-vpc-mappings
```

**Response:**

```json
{
  "mappings": [
    {
      "id": "vpc-map-1713178200000",
      "networkId": "net-1713178190000-xyz",
      "awsVpcId": "vpc-0abcd1234efgh5678",
      "region": "us-west-2",
      "status": "active"
    }
  ]
}
```

**CLI Command:**

```bash
$ show-mappings
```

## Schema Translation Rules

### CIDR Block Alignment

1. **Local Network CIDR** → **AWS VPC CIDR**
   - Direct 1:1 mapping for simplicity
   - Both environments use the same CIDR block
   - Example: 10.50.0.0/16 (local) → 10.50.0.0/16 (AWS)

2. **Subnet Mapping**
   - Local subnets are distributed across AWS Availability Zones
   - Each subnet maintains its CIDR in both environments
   - Example:
     - Local: subnet-001 (10.50.1.0/24)
     - AWS: subnet-xxx in us-west-2a (10.50.1.0/24)

### VNet Identifier Translation

```
Local VNet ID: mathieu_et_favvarrow
       ↓
AWS VPC ID: vpc-0abcd1234efgh5678
```

The mapping record maintains both identifiers for bidirectional lookups.

### Availability Zone Distribution

Subnets are distributed across multiple AZs for high availability:

| Local Subnet | Purpose   | AWS AZ     | AWS Subnet ID |
| ------------ | --------- | ---------- | ------------- |
| 10.50.1.0/24 | DMZ       | us-west-2a | subnet-xxx    |
| 10.50.2.0/24 | App Tier  | us-west-2b | subnet-yyy    |
| 10.50.3.0/24 | Data Tier | us-west-2c | subnet-zzz    |

## Network Topology Synchronization

### Route Table Mapping

Local routes are translated to AWS route tables:

**Local Route:**

```json
{
  "destination": "10.60.0.0/16",
  "gateway": "10.50.0.1",
  "priority": 100
}
```

**AWS Route Table Entry:**

```json
{
  "DestinationCidrBlock": "10.60.0.0/16",
  "GatewayId": "igw-xxxx" or "vgw-xxxx",
  "Priority": 100
}
```

### Security Group Translation

Local network security policies map to AWS Security Groups:

**Local Policy:**

- Allow TCP 443 from 0.0.0.0/0
- Allow TCP 22 from 10.0.0.0/8

**AWS Security Group Rules:**

```json
{
  "IpPermissions": [
    {
      "IpProtocol": "tcp",
      "FromPort": 443,
      "ToPort": 443,
      "IpRanges": [{"CidrIp": "0.0.0.0/0"}]
    },
    {
      "IpProtocol": "tcp",
      "FromPort": 22,
      "ToPort": 22,
      "IpRanges": [{"CidrIp": "10.0.0.0/8"}]
    }
  ]
}
```

## Operational Procedures

### Creating a New VPC Mapping

1. **Provision Local Network**

   ```bash
   $ create prod-network --cidr 10.100.0.0/16
   ```

2. **Add Subnets**

   ```bash
   $ subnet add net-xxx dmz-zone 10.100.1.0/24
   $ subnet add net-xxx app-tier 10.100.2.0/24
   $ subnet add net-xxx data-tier 10.100.3.0/24
   ```

3. **Create AWS VPC** (via AWS Console or CLI)
   - Create VPC with matching CIDR: 10.100.0.0/16
   - Create subnets in multiple AZs
   - Note the VPC ID (e.g., vpc-0abcd1234)

4. **Establish Mapping**

   ```bash
   $ vpc-map net-xxx vpc-0abcd1234
   ```

5. **Verify Mapping**
   ```bash
   $ show-mappings
   ```

### Updating VPC Configuration

When AWS VPC configuration changes:

1. Update local network configuration to match
2. Regenerate mapping if CIDR blocks change
3. Verify connectivity after changes

### Deleting VPC Mapping

1. **Remove AWS Resources First** (via AWS)
   - Delete VPC subnets
   - Delete route tables
   - Delete VPC

2. **Remove Local Mapping**
   ```bash
   $ delete net-xxx
   ```
   (This automatically removes associated VPC mappings)

## Monitoring and Troubleshooting

### Health Checks

Verify mapping status:

```bash
$ show-mappings
```

Look for `status: "active"` in output.

### Common Issues

**Issue**: VPC mapping creation fails

- **Cause**: Network ID doesn't exist
- **Solution**: Verify network with `list` command first

**Issue**: CIDR conflict

- **Cause**: CIDR block overlaps with existing VPC
- **Solution**: Use non-overlapping CIDR ranges

**Issue**: Mapping shows as "error"

- **Cause**: AWS VPC may have been deleted
- **Solution**: Recreate AWS VPC or remove mapping

### Logging

All VPC mapping operations are logged:

- Timestamp of operation
- User/system performing operation
- Operation type (create/update/delete)
- Operation result (success/failure)
